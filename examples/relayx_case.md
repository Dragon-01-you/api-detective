## 取证发现时间线

### 第一步：零成本侦察就露馅了

还没花一分钱对话费，`recon` 阶段就有收获：

- `/v1/models` 的 `owned_by` 字段直接暴露了上游货源目录：deepseek / nvidia / z-ai / kimi / qwen 五个供应商混在一起——**官方直连的站点不会同时挂着 NVIDIA NIM 命名空间的模型**
- 错误措辞矩阵显示网关是 Express 系框架，与宣称的「DeepSeek 官方转发」架构不符
- 公开的设置接口泄露了后台导航项和第三方平台集成痕迹

### 第二步：身份测谎 —— 所有模型都「改口」

对全部 8 个 SKU 发起多语言身份测谎（中/英/日/俄 × 直接/间接/嵌入/翻译共 13 种问法）：

| 现象 | 解读 |
|---|---|
| 中文身份问题几乎 100% 被改道到同一个型号回答 | 内容路由欺诈：风控把敏感问题统一转给某个指定渠道 |
| 英文提问则能问出不同答案（部分承认来自其他厂商） | 路由只针对中文关键词，英文是漏网之鱼 |
| Fisher 精确检验 p < 0.001 | 这是系统性路由，不是随机巧合 |

### 第三步：提示词提取 —— 三层注入模板现形

用提示词武库（20 种技术 + 对抗性变体）成功让多个渠道逐字复述系统消息：

```
第一层：英文身份伪装层（要求模型自称特定型号）
第二层：中文皮肤层（中文场景下的身份话术）
第三层：思维链指令层（XML 标签包裹的 thinking_mode 指令）
```

关键验证手段：
- **间隔复测逐字一致** → 排除模型临场编造，确认是真模板
- **pt 算术交叉验证** → 用 token 用量反推系统提示词体积，任何「背出来的假提示词」都过不了这一关

### 第四步：现场抓获渠道轮换

对同一 SKU 在 60 秒内发起两次相同探测：

- 第 1 次：命中 A 厂商后端（注入模板 pt≈242）

→ 渠道池轮换实锤：你买的「一个模型」，实际上是多家供应商随机拼装的盲盒。

## 方法论要点回顾

1. 先零成本侦察，再花钱对话——预算永远花在刀刃上
2. 单一问法不可信，多语言 × 多问法矩阵才能识破内容路由
3. 任何「提示词」必须过稳定性复测 + pt 算术两道关，否则只是模型编的故事
4. 同一请求重复多次，轮换的渠道自己会暴露
5. 计费数据是最诚实的证人——分词器不会说谎
